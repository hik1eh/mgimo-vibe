# Цифровой деканат будущего

Конкурсный прототип личного кабинета вымышленного Университета Северного кампуса. Студент видит, что изменилось в расписании, как идёт семестр и когда будет готова справка. Сотрудник деканата обрабатывает заявки и публикует изменения для своего факультета. Преподаватель ведёт журнал своих занятий.

## Что умеет кабинет

| Требование задания | Как оно реализовано |
| --- | --- |
| Вход и профиль | Вход по логину и паролю. В профиле студента видны ФИО, факультет, направление, курс и группа. |
| Расписание | Ближайшее занятие на главной, расписание на неделю, время, корпус, аудитория и преподаватель. Переносы и отмены выделяются в расписании. Для поддерживаемых аудиторий Северного корпуса доступен маршрут во внутренней 3D-модели с выбором этажа и текстовыми указаниями. |
| Успеваемость | Оценки, зачёты, даты контрольных мероприятий и ожидаемые результаты по дисциплинам. «Итоги семестра» собирают прогресс, посещаемость и контрольные точки из данных студента. |
| Заявки и справки | Студент выбирает вид заявки, отслеживает статус и отвечает на уточнения в карточке. По четырём типам заявок можно получить демонстрационный PDF. По заявлению на академический отпуск и обращению в деканат ответ приходит в карточку. |
| Уведомления | На странице «Сегодня» видны объявления кампуса и ближайший зачёт или экзамен. В «Уведомлениях» есть учебные напоминания и персональные сообщения о переносах и ходе обработки заявок. Сотрудник может публиковать адресные объявления для факультета или группы. |

В меню «Дополнительно» есть справочник преподавателей группы с дисциплинами и демонстрационными рабочими адресами. Преподаватель может отметить посещаемость и выполнение контрольных точек. Студент видит свои отметки в кабинете.

В демонстрационной базе есть расписание на период **1 ноября — 20 декабря 2026 года** для двух групп, 211 занятий, 14 преподавателей, объявления и результаты контроля. На чистой базе «Сегодня» открывается на учебной дате **13 ноября 2026 года**, когда у группы ОН-201 показан перенос занятия из аудитории 305 в 412.

## Локальный запуск

Понадобятся Python 3 и работающий Docker Engine с плагином Docker Compose. На Windows и macOS запустите Docker Desktop и дождитесь готовности движка. Команды выполняются из папки, где лежит `compose.yaml`.

```sh
python scripts/init_env.py
docker compose up --build -d --wait
docker compose ps
```

Первая команда создаёт локальный `.env` с паролями демоаккаунтов. Compose запускает PostgreSQL и приложение, применяет миграции и загружает демонстрационные данные. Когда у обоих сервисов статус `healthy`, откройте [кабинет на localhost:8000](http://localhost:8000). [Проверка готовности API](http://localhost:8000/api/v1/health) доступна без входа.

| Логин | Роль и данные | Где взять локальный пароль в `.env` |
| --- | --- | --- |
| `student.a` | Алина Ветрова, факультет общественных наук, ОН-201 | `DEMO_STUDENT_A_PASSWORD` |
| `student.b` | Марк Леснов, факультет цифровых технологий, ЦТ-202 | `DEMO_STUDENT_B_PASSWORD` |
| `staff.a` | Сотрудник деканата факультета общественных наук | `DEMO_STAFF_PASSWORD` |
| `teacher.a` | Преподаватель социологии | `DEMO_TEACHER_PASSWORD` |

Для одновременной проверки нескольких ролей удобно открыть отдельные профили браузера. `docker compose stop` останавливает стенд с сохранением данных. Подробности запуска и команды для повторения проверок доступны в [RUNNING.md](RUNNING.md).

## Сценарии проверки

1. **Вход и данные студента.** Войдите под `student.a` и откройте «Профиль». Проверьте факультет, направление и группу. Повторите под `student.b` в отдельной сессии. Профиль и учебные данные должны соответствовать выбранному студенту.
2. **Перенос и маршрут.** Под `student.a` откройте на странице «Сегодня» объявление о переносе занятия из 305 в 412. Перейдите к занятию и откройте маршрут. Переключите этажи и сравните участок пути с текстовыми указаниями. Адресное объявление группы ОН-201 отсутствует в кабинете `student.b`.
3. **Успеваемость и журнал.** Откройте «Успеваемость» под `student.a`, посмотрите оценки, даты предстоящих зачётов и «Итоги семестра». Под `teacher.a` откройте журнал занятия «Социология повседневности» и сохраните отметку посещаемости или контрольной точки для Алины Ветровой. После обновления кабинета `student.a` увидит изменение в «Итогах семестра».
4. **Справка от заявки до PDF.** Под `student.a` подайте «Справку об обучении» и обновите страницу. Заявка должна остаться в списке. Под `staff.a` возьмите её в работу и запросите уточнение. Ответьте из карточки студента, затем отметьте справку готовой в очереди сотрудника. Студент получит уведомление и сможет скачать PDF с пометкой «Демонстрационный образец».
5. **Изоляция данных.** В сессии `student.b` откройте ссылку на заявку из предыдущего сценария. Интерфейс сообщит, что заявка недоступна. При прямом запросе к API за чужой заявкой или её PDF сервер возвращает HTTP 404. В очереди `staff.a` видны заявки своего факультета.
6. **Телефон.** На ширине 360 px повторите вход, просмотр расписания, подачу заявки и открытие уведомления.

## Архитектура и защита данных

| Слой | Реализация |
| --- | --- |
| [Интерфейс](frontend/) | React, TypeScript и Vite. Three.js используется для визуализации кампуса и маршрута по этажам. |
| [Сервер](backend/app/) | FastAPI обслуживает собранный интерфейс и API `/api/v1` на одном адресе. Сервер проверяет права, обрабатывает статусы заявок, создаёт уведомления и формирует PDF. |
| [Хранение и миграции](backend/migrations/) | PostgreSQL, SQLAlchemy и Alembic. База хранится в именованном томе Docker. Повторный запуск наполняет недостающие демоданные и сохраняет пользовательские записи. |
| [Окружение](compose.yaml) | Docker Compose связывает приложение и базу. Порт стенда привязан к локальному адресу. |

Пароли хешируются с Argon2id. Идентификатор сессии передаётся в cookie с флагом `HttpOnly`, в базе хранится его хеш. При изменении данных сервер проверяет источник запроса и CSRF-токен. Защищённые запросы проверяются по роли и принадлежности данных. Студент открывает свои заявки и документы, сотрудник работает в пределах факультета, преподаватель — со своими занятиями. Секреты загружаются из окружения. Подробнее в [техническом описании](docs/03-technical.md) и [коде авторизации](backend/app/security.py).

## Проверки и соответствие условиям конкурса

- **Работающий прототип и мобильная версия.** В итоговом локальном прогоне 19 ноября 2026 года прошли 50 серверных тестов, 12 модульных тестов интерфейса и 13 сценариев Playwright. Браузерные проверки включали размеры 360 и 1440 px, вход без WebGL, журнал, изменение расписания, подачу заявки и получение PDF. [Журнал реализации](docs/07-implementation-log.md)
- **Изоляция данных и тестовые аккаунты.** Автоматические тесты проверяют отказ в чтении и изменении чужой заявки, отказ в скачивании чужого документа и ограничение очереди по факультету. В стенде подготовлены два студента разных факультетов, сотрудник и преподаватель. [Серверные тесты](backend/tests/test_workflow.py) · [Браузерный сценарий](e2e/tests/workflow.spec.ts)
- **Вымышленные данные и оформление.** Университет, профили, занятия, результаты и документы придуманы для демонстрации. В интерфейсе используются собственная монограмма «СК» и отметка «Конкурсный прототип». [Продуктовое описание](docs/01-product.md)
- **Сторонние материалы.** Тексты лицензий шрифтов Lora, Manrope и Allura включены в исходники. Там же находятся уведомления для библиотек и иконок интерфейса и лицензия шрифта, встраиваемого в PDF. [Лицензии шрифтов](frontend/public/assets/font-licenses/) · [Уведомления интерфейса](frontend/public/assets/third-party-notices.txt) · [Лицензия DejaVu](backend/app/assets/LICENSE-DejaVu.txt)
- **Доступность для жюри.** Подтверждён локальный запуск через Docker. Ссылка на работающий прототип предоставлена в личном кабинете хакатона.
