# «Сегодня» и «Расписание»: лента и календарь

18 ноября 2026. Задание — `docs/frontend-redisign.md`. Изменены студенческие страницы «Сегодня» и «Расписание», интеграция с существующим API и проверки. Другие разделы, авторизация и серверные правила доступа сохранены. Коммит реализации — `41abe95`.

## Интерфейс

На двух страницах применены фон #F4F6FA, белые поверхности, navy #102A40/#0C2234, синий #245BAB, контейнер до 1240 px и радиусы 10–16 px. Только H1 этих страниц использует локальный кириллический Marck Script: [источник Google Fonts](https://github.com/google/fonts/tree/main/ofl/marckscript), [SIL OFL в приложении](../frontend/public/assets/font-licenses/MarckScript-OFL.txt). Обычный текст остаётся в Manrope. Новые фотографии не генерировались; сохранены чёткие локальные фотографии кампуса и лестницы.

Баннер — 200 px на десктопе и 145 px на телефоне. Фотография выступает вниз на 12/8 px; следующий блок резервирует место. Первый показ немедленный. При переходе между разделами заголовок проявляется и поднимается на 7 px за 260 мс, фото — от opacity .35 с подъёмом на 8 px за 320 мс; кривая cubic-bezier(.22,.8,.24,1). Изменение даты, режима и фильтров не пересоздаёт заголовок/фото. Клавиатура и reduced motion отключают переходы.

Лента «Симметрия» показывает пять уникальных квадратов на широком экране, три на среднем, на телефоне — native scroll-snap и ручные стрелки. Автопрокрутки нет. Закреплённое объявление имеет приоритет, затем применяется дата публикации и стабильный ID. Стрелки циклические: доступны при двух и более записях; при одной нет счётчика и стрелок. Крупный центральный квадрат тёмный. Hover увеличивает только саму карточку, раскрывая зарезервированное дополнение; сетка и нижние блоки остаются на месте. Touch не увеличивает карточки.

Каждая карточка — одна кнопка. Клик, Enter, Space и тап открывают одинаковый диалог с полным текстом и актуальным связанным занятием. Для trap/возврата фокуса и Esc установлен [Base UI Dialog](https://base-ui.com/react/components/dialog), версия `@base-ui/react` 1.9.0 зафиксирована в lock-файле. Из диалога есть настоящая ссылка на занятие. При истечении сессии диалог закрывается перед повторным входом.

Ниже ленты находятся ближайшее занятие, зачёт и текущая заявка, когда API возвращает соответствующие данные. Сохранены переходы к занятиям, оценкам, заявкам и заказ справки. Демонстрационные названия и семь объявлений проверочного набора не включены в приложение.

Расписание поддерживает день и неделю, шаг ±1/±7, календарную дату, «Сегодня», три фильтра по логике И и общий сброс. Десктопная неделя — семь колонок и ось «Начало», одновременные занятия остаются отдельными ссылками. На узких экранах неделя показывает все семь дат повесткой; строки совпадают с режимом дня. Перенос и отмена обозначены текстом. URL хранит `view`, `date`, `group`, `teacher`, `room`; явное `all` отличается от отсутствующего параметра. Переход в детали и возврат сохраняют состояние; последнее состояние календаря в sessionStorage используется также ссылкой из новости. Пустой период, нулевое пересечение, загрузка и ошибка различаются. Ответ старого запроса игнорируется.

## Соответствие API

| Интерфейс | Штатные поля/источник |
|---|---|
| Учебная дата, понедельник недели, «Сегодня» | `GET /api/v1/study-context`: `today`, `demo_day`, `timezone`; вычисления в Europe/Moscow |
| Новость и её источник | `GET /api/v1/announcements`: `id`, `title`, `text`, `source`, `audience`, `pinned`, `published_at`, `status`; API выбирает опубликованные адресные записи |
| Полный текст новости | `GET /api/v1/announcements/{id}`; полные данные заново запрашиваются при открытии |
| Перенос в ленте и актуальное занятие | `Announcement.lesson.id`, `starts_at`, `room`, `building`, `status`, `changes[].before.room`; ссылка на `/schedule/{id}` |
| Период расписания | `GET /api/v1/schedule?start=YYYY-MM-DD&end=YYYY-MM-DD`; один ограниченный диапазон понедельник–воскресенье, в том числе для коротких списков фильтров режима дня |
| Группа | `Lesson.group_id` — значение фильтра, `Lesson.group` — подпись. По умолчанию `mine` сопоставляется с `User.group` |
| Преподаватель | `Lesson.teacher` — единственное существующее поле. До появления `teacher_id` используется составной ключ JSON `["teacher", name]`, без выдуманного числового ID |
| Аудитория | `Lesson.building` + актуальное `Lesson.room`; составной ключ JSON `["room", building, number]` различает одинаковые номера в разных корпусах |
| Время, карточка, отмена/перенос | `Lesson.id`, `subject`, `kind`, `starts_at`, `ends_at`, `status`; детали и `changes[]` — прежний штатный экран |
| Краткие блоки главной | API расписания, `academic-results.summary.next_credit`, собственные `requests`; приоритет заявки с `needs_info` |

API расписания студента разрешает только его группу. «Все группы» означает все данные, **уже разрешённые сервером**; клиент не расширяет область доступа. Списки формируются из разрешённой недели, полная база не скачивается. Синтаксически неверные параметры получают безопасные значения. Числовой ID выбранной группы сохраняется и в пустой неделе; без серверного справочника нельзя определить существование группы по отсутствию занятий. Неизвестный ID не раскрывает данные и даёт пустой результат.

## Проверочные команды

Из корня `dekanat-handoff`, с подготовленным локальным `.env`:

```powershell
npm.cmd --prefix frontend test
npm.cmd --prefix frontend run build
docker compose -p dekanat-qa -f compose.qa.yaml up --build -d --wait db app
docker compose -p dekanat-qa -f compose.qa.yaml build browser
docker compose -p dekanat-qa -f compose.qa.yaml exec -T app python -m app.qa --reset-test-data
docker compose -p dekanat-qa -f compose.qa.yaml run --rm --no-deps browser npx playwright test student-redesign.spec.ts cabinet-header.spec.ts premium.spec.ts layout.spec.ts states.spec.ts workflow.spec.ts compatibility.spec.ts
```

Сброс в этой последовательности разрешён только guard-проверкой имени базы `dekanat_e2e_test`. Рабочая база не сбрасывается. Cookies остаются в памяти браузерных контекстов; trace/storageState/видео с вводом паролей не записываются.

Фактически пройдены **11 unit-тестов** (семь новых для календаря) и **38 уникальных браузерных сценариев** по основному прогону и точечным повторениям:

| Запуск | Фактический результат |
|---|---|
| TypeScript/Vite локально и в Docker | PASS; сохранено прежнее предупреждение о ленивом 3D chunk экрана входа около 560 kB |
| Основной набор из семи spec-файлов | 36 passed / 1 failed за 160,6 с. Падение HiDPI: тест проверял загрузку старого фото, а измерял уже новое с naturalWidth=0 |
| Исправленный HiDPI + новый сценарий настоящей авторизации | 2 passed за 7,0 с; ожидание теперь включает заголовок нового раздела, src нужного изображения и его загрузку |
| Усиленное пересечение трёх конкретных фильтров, reload и возврат | 1 passed за 4,1 с |
| Окончательный захват статичных состояний | 1 passed за 5,6 с; скриншоты fast-forward конечных CSS-переходов, фактический hover измерен отдельно |

Проверены: 0/1/3/7 новостей, пять/три квадрата, стабильность геометрии и крайние hover-карточки, Enter/Space/Esc, trap/возврат фокуса, axe диалога, свайп и стрелки тапом, ширины 360/390/1024/1440, пересечение и нулевой результат, разные корпуса с номером 412, старый 305, отмена и совпадающий слот, URL/reload/возврат из деталей, пустая неделя с сохранением группы, ошибка/повтор и старый задержанный ответ. Общие проверки добавляют 52 экрана обеих ролей с axe/overflow, шапку до 1916 px и DPR 2, WebKit 360 и Firefox 1440, клавиатуру и reduced motion.

На настоящем API выполнены входы трёх аккаунтов, сохранение заявки после reload, уточнение/ответ/завершение, уведомление и скачивание PDF. Другому студенту отказано в доступе к заявке, документу и уведомлению; сотруднику — к заявке чужого факультета. Прошли правка аудитории 305 → 412, публикация/правка/снятие адресного объявления и изоляция другого факультета. Дополнительный реальный сценарий подтверждает, что «Все группы» возвращает только разрешённую группу студента Б, подстановка ID группы А даёт нулевое пересечение, а прямой запрос чужого занятия — 404.

Предыдущие промежуточные падения: слишком ранняя проверка корпуса после перехода; мгновенная проверка фокуса до обработки focus-guard; тест оставлял принудительную CDP touch-эмуляцию перед кликом мышью. Исправлены ожидания нового заголовка и устойчивого фокуса, режим мыши восстановлен перед mouse-click; отдельно прошёл настоящий tap на циклической стрелке. Серверные утверждения и проверки аудитории сохранены. Финальные статичные hover-кадры пересняты после обнаружения кадра середины перехода; [метрики](assets/student-redesign-hover-metrics.json) подтверждают scale 1.06/подъём 5 px, opacity дополнения 1 только у наведённой карточки и 0 у соседей.

JSON-история находится локально в `artifacts/browser/student-redesign/results-round-*.json`, `results-followup.json`, `results-intersection.json`, `results-capture.json`; HTTP-сверка — `main-http.json`. Для точечных повторений использовались:

```powershell
docker compose -p dekanat-qa -f compose.qa.yaml run --rm --no-deps browser npx playwright test cabinet-header.spec.ts student-redesign.spec.ts --grep 'HiDPI|real API authorization'
docker compose -p dekanat-qa -f compose.qa.yaml run --rm --no-deps browser npx playwright test student-redesign.spec.ts --grep 'day/week filters intersect'
docker compose -p dekanat-qa -f compose.qa.yaml run --rm --no-deps browser npx playwright test student-redesign.spec.ts --grep 'capture redesign evidence'
```

## Ограничения и ожидаемый серверный контракт

- Исходный интерактивный `dekanat-preview.html` не найден в репозитории и доступных загрузках. Реализация и визуальная проверка опираются на подробное письменное ТЗ; попиксельное совпадение с недоступным HTML не заявляется.
- Реальный просмотр нескольких групп пока не разрешён API студента. Проверка одновременных занятий разных групп использует явно обозначенный мок только в Playwright; она проверяет интерфейс, а не наличие такого серверного разрешения. Для расширения нужен серверный список разрешённых групп с `id/name`, `User.group_id` и соответствующая выборка расписания с серверной проверкой прав.
- `teacher_id` и `room_id` отсутствуют. Составные ключи корректны для текущего демонаполнения и разных корпусов, но не различают двух преподавателей с одинаковым именем или переименованные помещения. Для полного требования нужны стабильные ID в Lesson и разрешённые справочники преподавателей/помещений с подписями и корпусом.
- В проекте нет карты, координат/цели маршрута, API маршрута или штатного действия «Показать маршрут». Кнопка, притворяющаяся рабочей, не добавлена. Нужны `room_id → route_target` и существующий экран/сервис маршрута; он должен использовать текущую аудиторию и не открываться для отменённого занятия.
- Физические телефоны, ручной скринридер и аппаратная плавность не проверялись. Публичное размещение/HTTPS и внешняя доступность по-прежнему отложены владельцем. Отдельный серверный suite и проверка сохранения после перезапуска БД в этой фронтенд-итерации не повторялись.
