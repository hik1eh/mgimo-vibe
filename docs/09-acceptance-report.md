# Локальная приёмка T06 и Docker

Дата: 13 ноября 2026, Москва. Сборка исходников: `d72dd30`. Все профили, сообщения, учебные записи и документы вымышлены. Публичный релиз отложен по решению владельца: на этом этапе используется только Docker.

## Результат

Основное приложение: **http://localhost:8000**. Сервисы `app` и `db` проекта `dekanat-handoff` запущены и healthy. PostgreSQL 17 хранит данные в именованном томе. Основные пользовательские данные не сбрасывались; мутационные браузерные проверки работали в отдельном проекте `dekanat-qa`, базе `dekanat_e2e_test` и отдельном томе.

Проверено: **36 серверных тестов в Linux-контейнере, 4 теста утилит, 15 браузерных проверок**. Все прошли. Отдельно выполнена начальная фиксация интерфейса «до». В актуальных JSON-отчётах браузера: 11 + 3 + 1 успешных проверок, 0 unexpected, 0 flaky, 0 skipped. Сборка TypeScript/Vite, миграции и зависимости проходят. Остаётся одно DeprecationWarning Starlette/AnyIO — оно не влияет на выполнение.

## Среда и метод

- Docker Desktop 4.49, Engine 28.5.1, Linux amd64; Compose 2.40.3.
- Runtime: Python 3.13-slim, Node 22-alpine, PostgreSQL 17-alpine.
- Автоматический браузерный стенд Playwright 1.64.1; Chromium, Firefox, WebKit. Axe 4.11.1 с правилами wcag2a, wcag2aa, wcag21aa.
- Chromium: ширины 360, 390, 768, 1440 px, высота 1000 px. На каждой ширине — 8 студенческих и 5 сотруднических страниц, проверка переполнения и axe.
- Дополнительно: WebKit на 360 px и Firefox на 1440 px — вход, учебные экраны и создание/восстановление заявки.
- Мобильные проверки выполнены эмуляцией, включая touch-события Chromium. Это не физический телефон и не ручное тестирование скринридером.

Анализ axe не обнаружил нарушений выбранных автоматических правил на проверенных экранах. Это ограниченный автоматизированный результат, а не заявление о полной сертификации WCAG.

## Сохранность и изоляция

Во время `persistence.spec.ts` браузерные сессии студента и сотрудника удерживались в памяти. Остановлены и заново запущены QA-контейнеры приложения и PostgreSQL без удаления тома. После healthy-состояния проверены прежние cookie, профиль, список заявок, личные уведомления, расписание, результаты, видимые объявления, сотруднические публикации и история правок. Страница заявки восстановилась после reload. Сравнение снимков ответов успешно.

Основная БД не очищалась. Команда `app.qa --reset-test-data` допускается только для БД с точным именем `dekanat_e2e_test`. Cookie и пароли не записывались в storageState или trace. В текстовых артефактах выполнен поиск значений паролей из окружения — совпадений нет.

## Выявлено и исправлено

1. Старт QA мог опередить миграции. В Compose добавлен healthcheck API и ожидание healthy.
2. Обращение к внутреннему адресу `http://app:8000` давало в Chromium ERR_SSL_PROTOCOL_ERROR. Тестовый адрес заменён на DNS-алиас `web`, без отключения защиты браузера.
3. На HTTP-origin отсутствовал `crypto.randomUUID`, что роняло формы. Добавлен UUID v4 fallback на `crypto.getRandomValues` и отдельный тест.
4. Scroll-snap оставлял несколько пикселей отступа на краю ленты. Граничное состояние кнопок учитывает этот отступ; стрелки и touch-прокрутка проверены повторно.
5. У заполненных select/textarea уточнены стабильные доступные названия. Исправлены соответствующие шаги браузерного прогона; полный сценарий публикации теперь проходит.
6. Повторный вход получил focus trap, фон inert и обновление ресурсов после восстановления сессии. Черновик сохраняется при реальном 401 и повторном входе.
7. Стили сведены к токенам палитры, типографики, отступов и радиусов; введена таблица очереди на десктопе и карточки на телефоне. На телефоне возвращено быстрое действие заказа справки.
