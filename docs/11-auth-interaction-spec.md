# Экран входа: спецификация перед реализацией

14 ноября 2026. Задание — `docs/2-front-sign-in` и приложенный пользователем референс sign-up. Это обновление существующей аутентификации; регистрации, социальных провайдеров и новых прав не добавляем.

## Разбор источников

Три предоставленных MP4 скачаны в системный Temp, вне проекта. Декодированы **30 кадров/с**, просмотрены последовательности и контактные листы. Sign Up — 310 кадров / 10,333 с; Type Face — 288 / 9,600 с; Carousel — 431 / 14,367 с. Страницы X не отдали содержимое; видео являются спецификацией. Исходный 3D-меш и CSS авторов недоступны, поэтому форма головы и параметры кривых воспроизводятся самостоятельно, без заявления об идентичности исходному коду.

- **Sign Up**: два верхних прожектора направляют свет на активное поле; неактивное состояние гасит лучи; ошибка меняет свет. Начало появления луча около кадра 30, плато около 44–46: приблизительно 0,5 с. Проверены яркость участка луча и последовательность кадров. Наивысшая скорость в начале, затем плавное замедление: используем существующую рекомендацию `cubic-bezier(0.23, 1, 0.32, 1)`, а не выдаём её за измеренный оригинальный CSS.
- **Type Face**: строки мелкого текста формируют вращающийся бюст; сборка видна примерно 0–2 с, цельная голова — около 2–7 с, исчезновение — 7–9,6 с. Период 9,6 с, линейный поворот. В нашей реализации — собственная процедурная поверхность головы и шеи с повторением **University North Campus**, без копирования модели/текста автора.
- **Carousel**: вертикальный поток карточек по искривлённой пространственной траектории, наклон/поворот и изменение масштаба; не плоский горизонтальный слайдер. Наблюдаемый ролик 14,367 с не доказывает точную длину оригинального бесконечного цикла: наш непрерывный цикл принят 14,4 с с равномерным сдвигом карточек.

## Композиция и переиспользование

Десктоп: общая скруглённая оболочка как в статическом референсе, **65% сцена / 35% вход**. Внутри сцены голова слева и вертикальная карусель справа. Палитра проекта: `--navy`, `--blue`, `--bg`, `--surface`, `--on-navy`, `--muted`; тёмная сцена и светлая форма. Собственный СК-монограм, русский контент, системная типографика `--font-sans`. Переиспользуются `signIn`, `User`, `ErrorBox`, серверные сессии, существующий focus trap повторного входа, типографика, spacing/radius-токены.

Новые токены в `tokens.css`: размеры оболочки/сцены и шрифта заголовка, производные navy-поверхности/границы/свет, мягкая тень, easing и длительности. Стили локализованы префиксом `auth-`, рабочие кабинеты не перекрашиваются. Новой библиотеки анимации нет: CSS transitions/keyframes для DOM, Three.js только для настоящего 3D-рендера. Phosphor даёт согласованные иконки глаз/стрелок/паузы.

## Состояния и переходы

| Компонент / состояние | Триггер | Изменение | Длительность / кривая |
|---|---|---|---|
| Оболочка / появление | Первый mount | opacity 0→1, translateY 12→0; один раз | 500 мс, ease-out; каскад формы 60 мс |
| Поле / focus | Pointer или Tab | Два луча поворачиваются к активному полю и проявляются; поле получает светлую поверхность | Лучи 500 мс ease-out, поле 200 мс; transform/opacity |
| Поле / idle | Уход фокуса из формы | Лучи гаснут, текст и подписи остаются читаемы | 500 мс ease-out |
| Кнопка / hover, pressed | Pointer / нажатие | Смещение стрелки, scale 0,985 при нажатии | 160 мс ease-out; hover только fine pointer |
| Форма / loading | Отправка | Кнопка disabled, «Входим…», индикатор; aria-busy | Реальная длительность API, spinner 800 мс linear |
| Форма / error | Отказ API | Текст role=alert, подсветка ошибки семантическим токеном; пароль не стирается при ошибке | Свет 500 мс; текст без тряски/прыжка |
| Форма / success | Успешный API | Открывается существующий кабинет по роли | Без искусственной задержки |
| Пароль / видимость | Кнопка-глаз | password↔text, aria-pressed, фокус остаётся на кнопке | Мгновенно |
| Голова | Видимая desktop-сцена | Реальный 3D-поворот и плавное появление/исчезновение | 9,6 с, linear; отрисовка при видимости |
| Карусель | Видимая desktop-сцена | translate3d + rotate + scale карточек | 14,4 с linear, равномерные фазовые сдвиги |
| Сцена / pause | Кнопка паузы; focus/hover карусели | Вращение головы и движение фото останавливаются в текущей фазе | Без перемотки к началу |
| Карусель / выбор | Стрелки/кнопки индекса | Выбор конкретного фото и остановка автодвижения | Клавиатура — мгновенно; pointer 240 мс ease-out |

На ширинах меньше 1000 px сцена вообще не монтируется: **только окно авторизации**, без загрузки WebGL и фотографий. На `prefers-reduced-motion` — статичная сцена, мгновенные управляющие переходы и без бесконечных циклов. При скрытии вкладки/сцены рендеринг приостанавливается. При недоступном WebGL остаётся типографический fallback; форма не зависит от 3D. Повторный вход после истечения сессии показывает только компактную форму с прежним focus trap и сохранением черновика.

## Материалы и проверка

Три фотографии кампуса — новые демонстрационные изображения вымышленного вуза, созданные встроенным Image Gen; exterior, library, atrium, единая navy/slate/ivory палитра. Их можно заменить своими файлами. Конечные WebP находятся в `frontend/src/assets` и импортируются через Vite, исходные PNG сохранены локально в игнорируемом `artifacts/auth-image-sources`; промпты сохраняются в отчёте реализации.

Проверки: 360/390/768/1000/1440; пропорция 65/35; отсутствие overflow; Tab/Enter, видимость пароля, pause/выбор фото; focus/idle/error/loading; реальный вход трёх аккаунтов; повторный вход с черновиком; reduced motion; отсутствие canvas/запросов фото на телефоне; отсутствие ошибок браузера. Встроенный browser host недоступен; пользователь **разрешил Docker Playwright** для визуальных и функциональных проверок в отдельном QA-стенде.

После реализации: отдельный каскад 60 мс не применяется — оболочка появляется одним переходом, поля не переигрывают анимацию. Фокус поля и ручной выбор фото меняются мгновенно; основной анимированный переход формы — лучи 500 мс. Первоначальные 200/240 мс таблицы относятся к плану, фактические значения зафиксированы в [отчёте](12-auth-update.md). В сцене проявление строк выполняется прозрачностью в shader; DOM-анимации используют transform/opacity. Без исходного меша точное совпадение геометрии не заявляется.
