# Фактический контракт T01–T04

Все пути имеют префикс `/api/v1`. OpenAPI доступен по `/docs`. Даты — ISO 8601 с часовым поясом. API не кэшируется. Нужна cookie серверной сессии; роль и владелец определяются по ней, идентификатор студента в теле заказа не принимается как источник прав.

| Метод и путь | Поведение |
|---|---|
| GET `/health` | Проверка подключения к БД |
| GET `/auth/csrf` | JSON `{csrf_token}`. Для гостя устанавливает HttpOnly pre-login cookie; для действующей сессии возвращает её токен |
| POST `/auth/login` | `{login,password}` → `{user,csrf_token}` и HttpOnly session cookie |
| POST `/auth/logout` | 204, удаляет запись сессии и cookie |
| GET `/me` | id, логин, роль, ФИО, факультет, группа, направление, курс |
| GET `/requests` | Только свои заявки студента, от новых к старым |
| POST `/requests` | `{purpose,idempotency_key}` → 201, карточка. Ключ — UUID, стабилен при повторной отправке одной формы |
| GET `/requests/{id}` | Только своя карточка с историей |
| POST `/requests/{id}/reply` | `{text,version}`. Только своя заявка `needs_info` → `in_progress` |
| GET `/requests/{id}/document` | PDF только владельцу при `ready` и наличии связанной записи документа |
| GET `/staff/requests?status=&q=` | Очередь своего факультета. q — подстрока номера |
| GET `/staff/requests/{id}` | Карточка только своего факультета |
| POST `/staff/requests/{id}/transitions` | `{action,version,text?}`. Действия: start, clarify, complete |
| GET `/notifications` | Личные уведомления студента, от новых к старым |
| GET `/notifications/{id}` | Только своё уведомление |
| PATCH `/notifications/{id}` | Без тела, идемпотентно отмечает своё уведомление прочитанным |

Все POST/PATCH требуют `Origin`, точно совпадающий с `APP_ORIGIN`, и `X-CSRF-Token`. Для входа сначала запросить `/auth/csrf`, затем отправить токен с pre-login cookie; после входа использовать токен из ответа. Для восстановления вкладки сначала `/auth/csrf`, затем `/me`. CSRF не хранится в localStorage, cookie сессии не доступна JavaScript.

401 — нет/истекла/отозвана сессия; 403 — неподходящая роль, Origin или CSRF; 404 — чужой или отсутствующий объект (содержимое не возвращается); 409 — устаревшая версия, недопустимый переход, неготовый документ или ключ отправки использован с другим текстом; 422 — поля не прошли проверку.

Статусы: `accepted` → `in_progress` → `ready`; уточнение: `in_progress` → `needs_info` → `in_progress` после ответа. Сотрудник не может завершить заявку, пока она ждёт ответа. Клиент посылает версию из карточки. Оптимистическая блокировка SQLAlchemy проверяет её и в UPDATE, поэтому параллельные операции не проходят вдвоём. При конфликте вся транзакция откатывается вместе с историей, документом и уведомлением. Создание защищено уникальным `(student_id, idempotency_key)` и повторно возвращает существующую заявку.

PDF генерируется при скачивании из вымышленных сведений. Публичного файлового пути нет. Кириллица обеспечивается включённым DejaVu Sans; лицензия лежит рядом в `backend/app/assets/`.

## Учебные данные T04

Все новые маршруты доступны только студенту. Нет сессии — 401, сотрудник — 403. Студент не задаёт группу или владельца результатов: они берутся из сессии. Чужое занятие по id — 404 без содержимого и истории.

| Метод и путь | Ответ |
|---|---|
| GET `/study-context` | `today` — сохранённая опорная дата сценария, `demo_day` — день показа занятий, `timezone=Europe/Moscow`, `demo_dates=true` |
| GET `/schedule?start=YYYY-MM-DD&end=YYYY-MM-DD` | Массив занятий своей группы, отсортированный по началу. Без start — опорная дата, без end — один день start |
| GET `/schedule/{id}` | Только своё занятие с той же структурой и историей изменений |
| GET `/academic-results?semester=3` | Свои доступные `semesters`, выбранный `semester`, `as_of`, `session_period`, массив `results` и `summary` |

Границы расписания включают обе даты и вычисляются по московским суткам: `starts_at >= start 00:00` и `< (end + 1 день) 00:00`. Максимум 31 день; неверные даты, обратный диапазон и крайняя непредставимая следующая дата дают 422. Привязка занятия к дню определяется его началом. Пустой день — массив `[]`, отменённое занятие остаётся в списке.

Занятие: id, group, subject, teacher, kind, starts_at, ends_at, building, room, status, version, changes. Статусы: `scheduled`, `moved`, `cancelled`. История содержит id, before/after (время, корпус, аудитория, статус), reason и created_at. Актуальные поля берутся из самой записи занятия. T04 даёт чтение; правка сотрудником входит в T05.

Учебный результат: id, subject, semester, kind (`credit`/`exam`), status (`upcoming`/`awaiting`/`published`), control_at, grade, credit_passed, passed, label. Числовая оценка допустима только для опубликованного экзамена (2–5); отметка зачёта — только для опубликованного зачёта. Неопубликованный результат не получает значение оценки. Ограничения закреплены в БД.

Без фильтра выбран максимальный семестр из собственных записей. Семестр 1–12 допустим; пустой семестр возвращает пустой массив и нулевую сводку. `summary.closed` — число опубликованных положительных зачётов и экзаменов от 3; `total` — число записей выбранного семестра; `awaiting` — число ожидающих результатов; `next_credit` — ближайший `upcoming` зачёт с датой не раньше `as_of`, либо null. `session_period` — минимальная и максимальная дата контроля в выбранных результатах, либо null.

Опорная дата сохраняется при первом `app.seed` из `DEMO_DATE` или московской даты запуска. Повторное наполнение не меняет её и существующие записи; интерфейс явно отмечает демонстрационные даты. Расписание, даты контроля и время истории отображаются в московском часовом поясе, независимо от часового пояса устройства.
