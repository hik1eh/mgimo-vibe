# Фактический контракт T01–T05

Все пути имеют префикс `/api/v1`. OpenAPI доступен по `/docs`. Даты — ISO 8601 с часовым поясом. API не кэшируется. Нужна cookie серверной сессии; роль и владелец определяются по ней, идентификатор студента в теле заказа не принимается как источник прав.

| Метод и путь | Поведение |
|---|---|
| GET `/health` | Проверка подключения к БД |
| GET `/auth/csrf` | JSON `{csrf_token}`. Для гостя устанавливает HttpOnly pre-login cookie; для действующей сессии возвращает её токен |
| POST `/auth/login` | `{login,password}` → `{user,csrf_token}` и HttpOnly session cookie |
| POST `/auth/logout` | 204, удаляет запись сессии и cookie |
| GET `/me` | id, логин, роль, ФИО, факультет, группа, направление, курс |
| GET `/requests` | Только свои заявки студента, от новых к старым |
| POST `/requests` | `{purpose,idempotency_key}` → 201, карточка. Ключ — UUID, стабилен при повторной отправке одной формы |
| GET `/requests/{id}` | Только своя карточка с историей |
| POST `/requests/{id}/reply` | `{text,version}`. Только своя заявка `needs_info` → `in_progress` |
| GET `/requests/{id}/document` | PDF только владельцу при `ready` и наличии связанной записи документа |
| GET `/staff/requests?status=&q=` | Очередь своего факультета. q — подстрока номера |
| GET `/staff/requests/{id}` | Карточка только своего факультета |
| POST `/staff/requests/{id}/transitions` | `{action,version,text?}`. Действия: start, clarify, complete |
| GET `/notifications` | Личные уведомления студента, от новых к старым |
| GET `/notifications/{id}` | Только своё уведомление |
| PATCH `/notifications/{id}` | Без тела, идемпотентно отмечает своё уведомление прочитанным |

Все POST/PATCH/PUT требуют `Origin`, точно совпадающий с `APP_ORIGIN`, и `X-CSRF-Token`. Для входа сначала запросить `/auth/csrf`, затем отправить токен с pre-login cookie. После входа использовать токен из ответа. Для восстановления вкладки сначала `/auth/csrf`, затем `/me`. CSRF не хранится в localStorage, cookie сессии не доступна JavaScript.

## Виды заявок и журнал преподавателя

| Метод и путь | Поведение |
|---|---|
| GET `/request-types` | Каталог с подписями полей и способом получения для студента и сотрудника |
| POST `/requests` | Поле `kind` различает `study`, `practice`, `military`, `retake`, `academic_leave` и `dean_message`. По умолчанию `study`. Повтор UUID с другим видом или текстом возвращает 409 |
| GET `/staff/requests?kind=` | Дополнительный фильтр очереди факультета по виду заявки |
| POST `/staff/requests/{id}/transitions` | Для `academic_leave` и `dean_message` необходимо непустое `text` при `complete`. Ответ сохраняется как событие `ready`, студент получает уведомление |
| GET `/teachers` | ФИО, дисциплины и вымышленная рабочая почта преподавателей группы студента |
| GET `/teaching/lessons`, `/teaching/lessons/{id}` | Занятия преподавателя на своём факультете. В карточке возвращаются активные студенты группы и их отметки |
| PUT `/teaching/lessons/{id}/journal/{student_id}` | `attendance` равна `present`, `absent` или `null`. `checkpoint` равна `completed`, `pending` или `null`. Версия новой отметки — 0, изменение увеличивает версию. Конфликт версии и закрытый журнал возвращают 409 |
| GET `/academic-results?semester=` | `engagement` содержит собственные отметки студента за выбранный семестр, общие числа и разбивку по дисциплинам |

401 — нет/истекла/отозвана сессия; 403 — неподходящая роль, Origin или CSRF; 404 — чужой или отсутствующий объект (содержимое не возвращается); 409 — устаревшая версия, недопустимый переход, неготовый документ или ключ отправки использован с другим текстом; 422 — поля не прошли проверку.

Статусы: `accepted` → `in_progress` → `ready`; уточнение: `in_progress` → `needs_info` → `in_progress` после ответа. Сотрудник не может завершить заявку, пока она ждёт ответа. Клиент посылает версию из карточки. Оптимистическая блокировка SQLAlchemy проверяет её и в UPDATE, поэтому параллельные операции не проходят вдвоём. При конфликте вся транзакция откатывается вместе с историей, документом и уведомлением. Создание защищено уникальным `(student_id, idempotency_key)` и повторно возвращает существующую заявку.

PDF генерируется при скачивании из вымышленных сведений. Публичного файлового пути нет. Кириллица обеспечивается включённым DejaVu Sans; лицензия лежит рядом в `backend/app/assets/`.

## Учебные данные T04

Все новые маршруты доступны только студенту. Нет сессии — 401, сотрудник — 403. Студент не задаёт группу или владельца результатов: они берутся из сессии. Чужое занятие по id — 404 без содержимого и истории.

| Метод и путь | Ответ |
|---|---|
| GET `/study-context` | `today` — сохранённая опорная дата сценария, `demo_day` — день показа занятий, `timezone=Europe/Moscow`, `demo_dates=true` |
| GET `/schedule?start=YYYY-MM-DD&end=YYYY-MM-DD` | Массив занятий своей группы, отсортированный по началу. Без start — опорная дата, без end — один день start |
| GET `/schedule/{id}` | Только своё занятие с той же структурой и историей изменений |
| GET `/academic-results?semester=3` | Свои доступные `semesters`, выбранный `semester`, `as_of`, `session_period`, массив `results` и `summary` |

Границы расписания включают обе даты и вычисляются по московским суткам: `starts_at >= start 00:00` и `< (end + 1 день) 00:00`. Максимум 31 день; неверные даты, обратный диапазон и крайняя непредставимая следующая дата дают 422. Привязка занятия к дню определяется его началом. Пустой день — массив `[]`, отменённое занятие остаётся в списке.

Занятие: id, group, subject, teacher, kind, starts_at, ends_at, building, room, status, version, changes. Статусы: `scheduled`, `moved`, `cancelled`. История содержит id, before/after (время, корпус, аудитория, статус), reason и created_at. Актуальные поля берутся из самой записи занятия. T04 даёт чтение; правка сотрудником входит в T05.

Учебный результат: id, subject, semester, kind (`credit`/`exam`), status (`upcoming`/`awaiting`/`published`), control_at, grade, credit_passed, passed, label. Числовая оценка допустима только для опубликованного экзамена (2–5); отметка зачёта — только для опубликованного зачёта. Неопубликованный результат не получает значение оценки. Ограничения закреплены в БД.

Без фильтра выбран максимальный семестр из собственных записей. Семестр 1–12 допустим; пустой семестр возвращает пустой массив и нулевую сводку. `summary.closed` — число опубликованных положительных зачётов и экзаменов от 3; `total` — число записей выбранного семестра; `awaiting` — число ожидающих результатов; `next_credit` — ближайший `upcoming` зачёт с датой не раньше `as_of`, либо null. `session_period` — минимальная и максимальная дата контроля в выбранных результатах, либо null.

Опорная дата сохраняется при первом `app.seed` из `DEMO_DATE` или московской даты запуска. Повторное наполнение не меняет её и существующие записи; интерфейс явно отмечает демонстрационные даты. Расписание, даты контроля и время истории отображаются в московском часовом поясе, независимо от часового пояса устройства.

## Лента и кабинет сотрудника T05

| Метод и путь | Поведение |
|---|---|
| GET `/announcements` | Только действующие опубликованные сообщения вуза, своего факультета и группы; закреплённые первыми, затем от новых |
| GET `/announcements/{id}` | Та же проверка аудитории и времени; чужое, снятое, будущее, истёкшее или черновик — 404 |
| GET `/staff/groups` | Только группы факультета сотрудника |
| GET `/staff/announcements` | Все состояния объявлений своего факультета и групп |
| GET `/staff/announcements/{id}` | Своя факультетская публикация/черновик; общевузовское и чужое — 404 |
| POST `/staff/announcements` | Создание с idempotency_key UUID, 201; точный повтор возвращает ту же запись |
| PATCH `/staff/announcements/{id}` | Полное редактируемое тело с version: правка, публикация, снятие |
| GET `/staff/schedule?start=&end=&group_id=&q=` | Свои занятия; по умолчанию неделя сценария; диапазон до 31 дня, поиск по дисциплине/преподавателю |
| GET `/staff/schedule/{id}` | Только занятие своего факультета с историей |
| PATCH `/staff/schedule/{id}` | Версионная правка или отмена, история и данные формы связанного объявления |

Объявление содержит title, text, source, audience, faculty_id, group_id, lesson_id, status, pinned, published_at, expires_at, version и необязательное `lesson` с актуальными полями и историей занятия. Поле `group_id` добавлено также в ответ занятия. Связь с группой/факультетом/занятием защищена составными внешними ключами и CHECK. Отдельные выдачи проверяют серверную сессию и роль при каждом запросе.

Редактируемое тело объявления: title (3–160), text (3–5000), audience (`faculty`/`group`), group_id или null, lesson_id или null, status (`draft`/`published`/`withdrawn`), pinned, expires_at или null. При создании добавить idempotency_key, при PATCH — version. faculty_id, author_id, source и published_at задаёт сервер, неизвестные поля отклоняются (422). Студент не может использовать staff API (403), сотрудник не создаёт общевузовские объявления. Ссылка на занятие разрешена только его собственной группе. При публикации/повторной публикации дату задаёт сервер; при правке действующей записи она сохраняется. Окончание показа должно быть позже даты публикации. Все входные datetime должны содержать часовой пояс.

Видимость объявления вычисляется по текущему серверному времени: status=published, published_at <= now и expires_at отсутствует или > now. Замороженная учебная дата не меняет окно показа новостей. При повторном переносе или отмене связанного занятия API возвращает его текущие параметры, а не сохранённую при публикации копию.

Тело правки занятия: version, action=`update` (по умолчанию) или `cancel`, reason (3–500), необязательные starts_at, ends_at, building, room. Группа, дисциплина и преподаватель этим маршрутом не меняются. Конец должен быть позже начала; пустая правка — 422. Изменение полей ставит status=moved; отмена — cancelled. Отменённая запись остаётся доступна, её дальнейшая правка/повторная отмена закрыта (409). Состояние занятия, версия и запись before/after с автором сохраняются одной транзакцией. Ответ дополнен `announcement_prefill`: audience=group, group_id, lesson_id, нейтральные title/text для формы публикации. Само объявление создаётся отдельным явным действием сотрудника.

Все изменения требуют прежние Origin + X-CSRF-Token. Устаревшая версия и параллельный проигравший запрос — 409 с откатом всей транзакции. Создание объявления защищено уникальным (author_id, idempotency_key) и отпечатком исходного тела: повтор того же тела не размножает записи; другое тело с прежним ключом — 409. Черновики форм хранятся только в sessionStorage, серверная версия при конфликте сравнивается явно.

Главная и расширенный список уведомлений используют существующие защищённые `/requests`, `/notifications`, `/academic-results`, `/schedule` и новые `/announcements`. Признак прочтения относится к личному уведомлению. Общие новости не копируются в персональные записи; учебное напоминание вычисляется из ближайшего зачёта текущего семестра.

## T06: окружение и восстановление интерфейса

Контракт API не менялся. Ключ отправки UUID v4 создаётся и в локальном HTTP-контексте через crypto.getRandomValues, если randomUUID недоступен. Сессия, CSRF и права по-прежнему проверяются сервером. При 401 интерфейс сохраняет черновик, блокирует фон атрибутом inert и открывает диалог входа с управлением фокусом; после восстановления обновляет ресурсы. HTTPS-конфигурация cookie Secure/HttpOnly/SameSite проверена отдельным тестом, внешний TLS этим не подтверждается.

`GET /api/v1/health` проверяет БД и используется healthcheck контейнера. Compose с `--wait` ждёт завершения миграций/seed и готовности API. `app.qa --reset-test-data` — только служебная команда для отдельной БД `dekanat_e2e_test`; в основной БД она отказывается работать. Публичный HTTP-маршрут для сброса не существует.
