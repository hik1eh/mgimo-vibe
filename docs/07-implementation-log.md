Дата: 13 ноября 2026, Москва. Это фактический технический прогон; пользовательские исследования не проводились.

## Исходное состояние и решения

В `E:\mgimo-vibe` обнаружен пакет требований `dekanat-handoff/`; исходников, зависимостей и Git не было. Корнем приложения выбрана эта папка. Прочитаны AGENTS и документы 00, 01, 02, 03, 04, 05. Существующие спецификации сохранены. Создан локальный Git; README изменён на диске, но не добавлен в коммиты согласно AGENTS. docs/06, templates и материалы об интервью не использовались.

Команды запуска также сохранены в версионируемом RUNNING.md, чтобы инструкции присутствовали при клонировании кода.

Стек из требований: React 19, TypeScript, Vite; FastAPI, SQLAlchemy 2, Alembic, PostgreSQL. Приложение отдаёт собранный фронтенд и API на одном origin. Docker Compose хранит БД в томе. Пакеты зафиксированы в npm lock и Python requirements.lock. PostgreSQL 17 указан для Compose; реальный локальный прогон выполнен на установленной 18.3, поскольку Docker Engine остановлен. Python Store alias не запускался; использован установленный Python 3.13.5.

T02: два факультета, две группы, три вымышленных пользователя. Согласованность группы и факультета защищена составным внешним ключом, роль и обязательные поля — CHECK. Argon2id, случайная серверная сессия с хешем токена, сроком и отзывом, HttpOnly cookie, Origin и CSRF включая login/logout. Пароли сгенерированы только в игнорируемый `.env`; не выведены и не включены в код.

T03: форма, список, прямая карточка, профиль, факультетская очередь с фильтрами/поиском, история, вопрос и ответ, готовность, личные уведомления с прочтением, PDF. Идемпотентность заказа — UUID одной отправки; версия заявки — защита переходов при конкуренции. Изменение, событие, уведомление и документ сохраняются одной транзакцией. Черновики формы/ответа хранятся в sessionStorage; пароль не сохраняется. Статусы подписаны текстом, формы имеют подписи, предусмотрены ошибки/пустые списки и CSS для телефона. Запланированные T04–T05 разделы не подменены заглушками.

## Итерации и наблюдения

1. Первый API-прогон: 9 из 10 тестов прошли; проверка текста PDF не учитывала перенос строки между словами «имеет» и «юридической». Извлечённый текст нормализован по пробелам. Повторный прогон: 10/10.
2. Уточнено ограничение курса: SQL CHECK без `IS NOT NULL` пропускает NULL. Добавлена миграция и проверка. Тестовая БД уже содержала предыдущую локальную редакцию миграции; фикстура изменена так, чтобы на каждом запуске проверять миграции base → head на выделенной `_test` базе. После исправления тест согласованности проходит.
3. Добавлен отдельный параллельный заказ с одним ключом: обе отправки возвращают одну заявку, событие не размножается. Итоговый набор: 11/11.
4. Первая сборка CSS предупредила о пустом @import; строка удалена. Повторная сборка прошла без этого предупреждения. Отдельный `alembic check` подтвердил отсутствие новых операций схемы.
5. Native Browser host недоступен. Резервный Computer Use сообщил `Computer Use native pipe is unavailable ... os error 2`; повторная попытка и сброс сессии не помогли. Браузерные действия, мобильные размеры и скриншоты интерфейса не выполнены, визуальное «до/после» не получено. Это ограничение среды, а не пройденная приёмка.

## T04 — расписание, результаты и сессия

13 ноября 2026, Москва. Продолжение существующего проекта, без сброса основной БД. Повторно прочитаны AGENTS, решения, продукт, задача T04, UI, техническое задание и приёмка. Сохранены стек, сессии, заявочный сценарий и правила исключения файлов из коммитов. Делегирование и дополнительные агенты не использовались.

Добавлена миграция `6cd823c33462` поверх T03: занятия, история изменений, учебные результаты и дата сценария. Учебные записи привязаны к своей группе/студенту; новая дата и ограничения формата результата проверяются БД. API проверяет роль и принадлежность для списков и прямой карточки. Изменение расписания сотрудником ещё не включено — это T05.

Демонаполнение расширено без изменения существующих записей: 7 занятий, 2 записи истории, 10 результатов за два семестра. У А — перенос 305 → 412, отдельная консультация в исходной аудитории 305 и отменённый семинар. У Б — собственные дисциплины и преподаватели. Воскресенье пустое. Опорная дата первого seed сохраняется; можно заранее задать DEMO_DATE. Повторный seed не двигает даты и не перезаписывает аудитории, оценки или пользовательские заявки. Такое поведение выбрано для воспроизводимого показа без сброса действий; интерфейс явно подписывает, какая дата считается «Сегодня» в демонстрационном сценарии.

Во фронтенде добавлены день/неделя, выбор даты, карточка занятия с прежними и текущими значениями, история отмены, фильтр семестра и даты сессии. Недельные колонки на широком экране сменяются переключателем дней и списком при ширине до 1100 px. Для телефона добавлены карточки результатов. Дата, режим расписания и семестр хранятся в URL и восстанавливаются после обновления. Прогресс считается по положительным опубликованным результатам, без зачёта пустых оценок и экзамена на 2. Подписи будущего зачёта и ожидаемой оценки различаются текстом. Время отображается по Москве.

Общие ErrorBox/useResource вынесены из main в ui.tsx. При смене диапазона или семестра hook скрывает данные прошлого запроса и отбрасывает запоздалый ответ; при ошибке появляется повторная загрузка. Дизайн сохраняет существующие токены и шапку; меню по центру на широком экране, на телефоне переносится на строки. Подпись поля даты сделана видимой. Время истории занятия приведено к тому же московскому часовому поясу, что и расписание.
