# T07 — локальный показ и передача исходников

Объём этого этапа: готовый локальный Docker-прототип, сценарий показа, фактический отчёт и архив исходников. Публичный релиз отложен владельцем. Материалы ниже описывают реализованное поведение и технические проверки; исследования пользователей не проводились.

## Запустить и проверить перед показом

Из корня приложения:

```powershell
docker compose up --build -d --wait
docker compose ps
.\.venv\Scripts\python.exe scripts/check_demo.py
```

Для чистого клона сначала выполните подготовку окружения и виртуальной среды из [RUNNING.md](../RUNNING.md). Приложение открывается на **http://localhost:8000**. `check_demo.py` проверяет вход/выход трёх аккаунтов, доступность разделов, разные факультеты/группы, адресность объявлений, учебные состояния и исходную консультацию. Он создаёт и отзывает только свои сессии; заявки, уведомления и учебные записи не меняет. Результат записывается в `artifacts/t07/local-readiness.json`, пароли и cookie в отчёт не попадают. Скрипт принимает только локальные HTTP-origin.

Если Docker уже работает, но локальной виртуальной среды ещё нет, для скрипта достаточно `python -m venv .venv` и `.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock`. Локальный сервер PostgreSQL для этой проверки не нужен.

| Участник | Логин | Пароль в локальном окружении |
|---|---|---|
| Алина Ветрова, студентка ОН-201, факультет общественных наук | `student.a` | `DEMO_STUDENT_A_PASSWORD` |
| Марк Леснов, студент ЦТ-202, факультет цифровых технологий | `student.b` | `DEMO_STUDENT_B_PASSWORD` |
| Ирина Речная, сотрудник факультета общественных наук | `staff.a` | `DEMO_STAFF_PASSWORD` |

Значения находятся в `.env`. Для локального просмотра только трёх паролей:

```powershell
Select-String -Path .env -Pattern '^DEMO_.*_PASSWORD='
```

Команда передаёт эти три демодоступа жюри отдельно. В архиве исходников рабочей `.env` нет. Seed не меняет пароли уже созданных аккаунтов: смена только `.env` не сбрасывает пароль в существующей БД.

## Сценарий показа — около пяти минут

Откройте три независимых профиля браузера: студент А, сотрудник и студент Б. Две вкладки одного профиля разделяют cookie, поэтому для одновременного входа под разными аккаунтами нужны разные профили или разные браузеры. Для студента А используйте мобильную ширину 360 px, для сотрудника — 1440 px.

| Время | Действие | Что показать |
|---|---|---|
| 0:00–0:40 | Войти студентом А, открыть «Сегодня», объявление о переносе и занятие | Связь объявления с актуальным расписанием, старую 305 и новую 412, дату демонстрационного дня |
| 0:40–1:00 | Студентом Б открыть главную и прямую ссылку на групповое объявление А | Общее сообщение видно обоим, чужая запись недоступна |
| 1:00–2:10 | А заказывает справку для «Учебного центра Орбита», обновляет страницу; сотрудник находит номер, берёт в работу и задаёт уточнение | Номер и история переживают reload, очередь ограничена факультетом |
| 2:10–2:50 | А отвечает в карточке, сотрудник завершает; А открывает уведомление и скачивает PDF | Полный путь запроса, отметку «Демонстрационный образец» и отсутствие юридической силы |
| 2:50–3:50 | Сотрудник в расписании выбирает «Консультация по социологии», меняет 305 → 412, сохраняет и публикует связанное объявление | Предзаполненную группу/ссылку, новую карточку у А, отсутствие у Б; прежнюю и новую аудиторию в истории |
| 3:50–4:20 | Отредактировать текст объявления, обновить у А, затем снять публикацию | Сохранение изменений, исчезновение снятого сообщения; отмену другого занятия можно показать отдельно |
| 4:20–5:00 | А открывает успеваемость и семестр | «Предстоит зачёт», «Ожидается результат», сводку из записей; завершить ссылкой на исходники и отчёт |

В демоданных дата расписания фиксируется при первом seed. Если сегодня другой день, используйте кнопку «Демонстрационный день» и неделю этой даты; консультация находится во вторник. Лента листается вручную, автоматического перелистывания нет. Уже изменённую консультацию скрипт готовности отметит предупреждением. Рабочую базу ради репетиции не сбрасывайте: для чистого прогона есть выделенный QA-стенд.

## Воспроизвести два полных UI-сценария отдельно от показа

```powershell
New-Item -ItemType Directory -Force artifacts/t07/browser | Out-Null
docker compose -p dekanat-qa -f compose.qa.yaml up --build -d --wait db app
docker compose -p dekanat-qa -f compose.qa.yaml exec -T app python -m app.qa --reset-test-data
docker compose -p dekanat-qa -f compose.qa.yaml build browser
docker compose -p dekanat-qa -f compose.qa.yaml run --rm --no-deps browser npx playwright test workflow.spec.ts
Copy-Item artifacts/browser/results.json, artifacts/browser/certificate-ui.pdf -Destination artifacts/t07/browser
docker compose -p dekanat-qa -f compose.qa.yaml stop
```

QA reset разрешён только для точного имени БД `dekanat_e2e_test`. Браузер использует проверенный каталог `artifacts/browser`; итоговые JSON и PDF копируются в папку T07. Скриншоты остаются в `artifacts/browser/after`. На текущем Windows-хосте новый bind mount `artifacts/t07/browser` доступен контейнеру только для чтения, поэтому прямая запись в него не используется. Основной Docker-проект продолжает работать. Полная матрица T06 и команды её повторения — в [отчёте приёмки](09-acceptance-report.md) и [RUNNING.md](../RUNNING.md).

## Архив для команды

После коммита изменений:

```powershell
python scripts/prepare_handoff.py
python scripts/prepare_handoff.py --verify artifacts/handoff/dekanat-source-<commit>.zip
```

Подставьте фактическое имя, которое выведет первая команда. Используется только стандартная библиотека Python и установленный Git. Архив строится из чистого Git HEAD, содержит исходники, миграции, lock-файлы, инструкции, технический отчёт и реальные скриншоты. В `HANDOFF-MANIFEST.json` записаны исходный commit, размер и SHA-256 каждого файла; рядом с ZIP создаётся его SHA-256. Одинаковый commit даёт одинаковые байты архива. Проверка `--verify` проверяет состав и хеши; для проверки подлинности сравните SHA-256 с отдельно переданным командой значением.

Архив не содержит `.env`, Git-историю, БД, сессии, сгенерированные артефакты, локальные заметки и материалы, исключённые AGENTS. Сборка также ищет в содержимом известные значения паролей/секретов текущего окружения. Это дополнительная проверка конкретных значений, а не универсальный аудит утечек. README остаётся на локальном диске по правилу AGENTS; точка входа в архиве — **RUNNING.md**.

| Материал | Текущее состояние |
|---|---|
| Работающий прототип | Локальный Docker: http://localhost:8000 |
| Исходники и инструкции | Локальный Git и проверяемый ZIP; remote репозитория пока не настроен |
| Отчёт и доказательства | [Фактическая приёмка T06](09-acceptance-report.md), [журнал](07-implementation-log.md), `docs/screenshots/`; результаты T07 ниже |
| Три демоаккаунта | Проверяются локально; пароли команда передаёт отдельно |
| Публичный HTTPS и проверка из России | Отложены владельцем |
| Доступ жюри к коду/отчёту в приватном окне | Проверить после публикации ссылок |

Черновик комментария капитана для заполнения после релиза:

> «Цифровой деканат» — конкурсный прототип вымышленного университета. Прототип: [публичный HTTPS URL]. Исходники: [ссылка с доступом жюри]. Отчёт: [ссылка]. Вход: student.a, student.b, staff.a; пароли передаются командой отдельно. Данные и PDF демонстрационные. Два сценария: адресный перенос занятия и справка с уточнением, уведомлением и скачиванием.

Это заготовка, она никуда не отправлена. После выбора хостинга настроить единый HTTPS-origin, `APP_ORIGIN`, `COOKIE_SECURE=true`, постоянный том и резервное копирование, затем выполнить A13/A14. Текущий loopback-порт Docker не является внешним релизом. Ручной скринридер и физические телефоны остаются непроверенными.
